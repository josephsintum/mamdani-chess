## Launch hardening: limits per IP

Found while load-testing on 2026-10-04 (`tools/loadgen`). Anyone can open as many live streams as they like, and each holds about 49 KB of server memory, so 10,000 streams is about 0.5 GB. The spec's abuse rules only cap reactions and body size. Before the public launch (milestone 07):

- Cap open streams per client IP (around 20; a household or office shares an IP, so not 1), answering 429 past the cap.
- Rate-limit API requests per IP (game creation especially: each game is a goroutine and about 6 KB).
- Behind Railway's proxy, take the client IP from `X-Forwarded-For` only from the proxy, not from any caller.
- Rerun `tools/loadgen` to check the caps don't trip real use: one player with a few tabs, a classroom on one IP.

## Launch check: HTTP/2

Found while watching agent-played games on 2026-10-04. Each open game tab holds one SSE stream for good, and over plain HTTP/1.1 a browser allows only 6 connections per host, shared by all tabs. With 6 game tabs open on one host, every other request from those tabs (piece SVGs, API calls) queues forever: the board draws without pieces and moves never send. Locally, `http://localhost:5173` hits this. In production, HTTPS lets browsers use HTTP/2, which multiplexes every tab over one connection, so the limit disappears, but only if HTTP/2 actually reaches the browser. In the Railway smoke test (milestone 07):

- Confirm the public URL serves HTTP/2: `curl -sI --http2 https://<domain>/ | head -1` shows `HTTP/2`, and the browser's Network panel shows protocol `h2` for `/api/games/*/stream`.
- Open 8 or more game tabs at once on the public URL and check that every board draws its pieces and moves still go through.
- If Railway's edge or the Go server ever fall back to HTTP/1.1, keep live updates working by capping streams per browser (one shared stream across tabs, or close the stream in hidden tabs) before launch.

## Observability and findings from the agent-played games

On 2026-10-04, 30 agents played games against each other through two separate headless browsers per game, in instant mode, with a third browser watching (20 complete games, 4,205 moves). Nothing failed:
- the server logged no errors, no panics and no 4xx or 5xx responses except 404s from tabs left open across a server restart;
- no browser logged a console error, warning or page exception;
- a move took 0.12 ms at the median and 2.1 ms at worst.

The run showed what the logs can't tell us. Every result had to come from the agents, not the server. Where each gap lands:

**Milestone 05 (Real games):**
- **One log line per game event:** created, Black joined, ended (reason, winner, number of moves), evicted, and (with persistence) restored after a restart or lost. Clocks, timeouts and first-move aborts add events of their own, so they belong in the same place. Log these at INFO.
- **A restart loses every game.** Two open tabs got 404 after a restart during the run. Saving games fixes this; check that a restored game's open tabs reconnect without a reload.
- **Clearer check status.** "Black to move — check!" doesn't say who is in check, and two agents read it as their own king. Name the side, e.g. "Black to move — Black is in check" or "Your move — you're in check".

**Milestone 07 (Launch):**
- **JSON log output.** Done in the playtest deploy: `LOG_FORMAT=json` in the production image, so the host's log search can filter on fields.
- **Moves at DEBUG.** One INFO line per request meant 4,205 move lines for 20 games. Keep game events at INFO and move requests at DEBUG.
- **A request ID and the client IP** (from `X-Forwarded-For`, trusted only from Railway's proxy, as for the per-IP limits) on every request line.
- **Refusals logged at INFO with the reason** (illegal move, stale `seq`, wrong turn), so a confused player's report can be traced.

**For the rules doc's "Watch in test games":** potholes swung many games. Queens and rooks fell in the first few rolls, and many decisive results came from falls rather than play. The players were language models, so treat this as a prompt for the playtest with friends, not a verdict.

**Not covered by the run, so cover it elsewhere:** the server's refusal paths (the test harness only sent moves the board showed as legal), reconnecting in the middle of a game, and spectators who join late.

## Leaderboards: open questions

### Player history (decided 2026-10-05, moved here from milestone 06)

Direction: remember players without ranking them. Chess.com and Lichess give guests no history or rating; casual browser games save progress against a guest ID and link it to an account later, which is our position.

- **Summary table:** `game_players(game, guest, color, name, opponent, opponent_name, outcome, reason, moves, lost_to_potholes, saved_by_mamdani, ended_at)`, indexed on `(guest, ended_at DESC)`, written in the same transaction as `EndGame`.
- **Per-side saves:** the game counts saves only for the whole game (`StatsJSON.Saved`), so this needs a per-side count.
- **Backfill:** replay finished games through `rules`. Only games with `rules = 2` replay: 06c retired the games saved under the old pothole rules, so history starts with 06c's first game.
- **UI:** "Your games" on home: stat chips (W/L/D, lost to potholes, saved by the Mamdani) and recent games.
- **Matching:** first come, first served until a rating exists.
- **Accounts, if ever:** an `accounts` table and a nullable `guests.account_id`. Signing in claims the current guest; each device links another guest. This works because games point to guest IDs and names are snapshots.

### Still open

Leaderboards were added on 2026-10-04 as an idea. They change two things the spec lists as out of scope: accounts and ratings. They need a short design pass before a plan, answering:

1. **Who is on the board?** Guests are a browser cookie, so clearing cookies or switching phones makes a new player. Options: keep guests and accept that, let a guest "claim" their name with a passkey or email link, or require sign-in only for the leaderboard.
2. **What is ranked?** A skill rating (Elo or Glicko from wins and losses), plain win counts, or fun pothole stats such as most pieces saved by the Mamdani, most pieces lost to potholes, or luckiest rolls. The fun stats need no accounts and fit "fun to watch".
3. **Which games count?** Only quick match, or friend games too? Friend games are easy to farm by playing yourself in two browsers.
4. **When?** It needs saved games (milestone 05). Before or after the public launch (milestone 07)?

### Weekly titles (decided 2026-10-05)

Partly answers question 2. A title belongs to whoever ranks first this week, and it can be lost. Titles reset every Monday at 00:00 New York time, so new players can win them; all-time numbers stay on a player's own history. Starting set:

| Title | Ranked by |
| --- | --- |
| GOAT | Most wins |
| Mayor | Most potholes repaired by your own Mamdani moves (one mayor at a time) |
| Capitalist | Most pieces taken per game, with at least 5 games that week. Only captures by your own moves; pieces a pothole swallows don't count. The joke: the Mamdani never captures (added 2026-10-06) |
| Pothole Magnet | Most of your pieces lost to potholes |
| Luckiest | Best saving-roll rate, with at least 20 saving rolls that week |

### Design pass (2026-10-06)

Sketches, each on desktop and phone: https://claude.ai/artifact/MMUKTL7M9pUKLD8PasthPF (local copy: `docs/superpowers/specs/2026-10-06-08-leaderboards-sketches.html`). Brainstorm notes and where to pick up: [`2026-10-06-08-leaderboards-brainstorm.md`](../specs/2026-10-06-08-leaderboards-brainstorm.md).

- **Titles are live.** Whoever leads right now holds the title, so it can change hands mid-week, even mid-game. Early in the week titles are vacant until someone is ranked. The leader at each reset is recorded as that week's winner.
- **Which games count (answers question 3):** quick match and friend games both, but a guest is ranked only after playing 3 different opponents that week. Farming then needs three fake guests.
- **Leaderboard page: direction A, the weekly list**, after Duolingo's leagues and Strava's Local Legend. Title tabs that fit across a phone, the holder and time left, a chart of where every player stands with you and the leader marked, then the top five under a "title line" and your own row among your neighbours. Hide the chart until about 20 players are ranked.

- **Player page:** one per player, opened from any name. Stats and recent games (history), this week's ranks and titles won (titles), then milestones and feats (milestone 09). The Pothole Atlas was dropped.
- **Fun facts:** a player's own numbers next to real NYC figures, with the source under each in small type. Only sourced numbers, computed from the player's saved games, and never a goal (so the Mamdani's distance stays a fact, not an achievement). Every game end shows one fact about that game, after wins and losses alike (self-mocking ones after a loss), never the same one twice in a row. ## Achievements: brainstorm (2026-10-05, milestone 09)

Ideas only; nothing here is agreed except the three kinds and weekly titles above. Every condition below comes from events the rules engine already emits (`rules/event.go`), so achievements can be backfilled by replaying saved games, as history is. A guest is a cookie, so clearing cookies loses them, the same as history.

**Rule for picking them:** each must be about potholes, dice, the Mamdani, or New York. Generic chess feats ("mate with a pawn") are out. Nothing may reward stalling (for example "move the Mamdani 100 times"), since stalling is already a playtest worry.

## Catchphrases: the idea (added 2026-10-05)

When something big happens on the board, a toast shows a short line, so the moment reads as an event (goal 5, "fun to watch"). It starts with the Mamdani falling into a pothole, with lines such as:

- "Rama is calling"
- "I got paperwork to do"
- "Ask ~~bat~~ Bruce Wayne for help"
- "Someone call 311" (New York's line for reporting potholes)

**How it could work:**
- Lines live in one file, keyed by event (`web/src/lib/catchphrases.ts`).
- The game page already gets each turn's events in `view.last`: `fell` (with the piece, `M` for the Mamdani), `saved`, `repaired`. When the dice for that event finish playing out, it calls `notify.info(line)`.
- A line is picked at random, never the same twice in a row, and shown to players and spectators alike.

**Other events that could get lines:**
- a saving roll that saves a piece;
- the Mamdani repairing a pothole;
- a queen falling in;
- a king saved by a re-roll;
- a win on time.

**To decide in a short design pass:**
1. **Whose voice.** The Mamdani is named after a real public figure, so lines in its voice read as words put in a real person's mouth. Keep them affectionate and clearly playful, never presented as real quotes, and review the full list before shipping. The same caution applies as for the Mamdani art (milestone 07).
2. **How often.** A toast on every saving roll could get noisy. Maybe only the Mamdani's own moments, plus rare ones.
3. **Who writes the lines.** They should be in the house voice and checked like the guest-name words ([docs/guest-names.md](../../guest-names.md)).
4. **Sound.** Sound settings are out of scope in the main spec, so text only for now. Milestone 13 may give some lines a sound.

## Sound: the idea (added 2026-10-07, milestone 13)

A game needs sound: short effects so each move and roll lands, and a soundtrack of New York streets under the board. The main spec lists sound settings as out of scope, so this milestone reopens that line.

**Effects, one per event.** Each comes from something the board already plays, so a sound starts with its animation:

| Event | Sound idea |
| --- | --- |
| Pick up, glide | A soft lift, maybe a short note that rises with the distance |
| Land | A wooden tap; a heavier one for a capture |
| Dice thrown, tumbling, landing | A rattle in the tray, a clack when each die stops |
| Pothole opens (even roll) | Asphalt cracking, maybe a jackhammer burst |
| Cone counts down, hole closes | A small cone tap; a steamroller or a shovel slap when it closes |
| Piece falls in | A drop and a far-off thud; the Mamdani's fall gets its own |
| Saving roll saves a piece | A hop and a short rising note |
| The Mamdani repairs a hole | The repair celebration's sound: sparks and a cheer |
| Check, checkmate | A horn honk for check, a longer flourish for mate |
| Clock under 10 s, "+5" | A ticking or a subway door chime; a coin sound for "+5" |
| Game over | A win sting and a loss sting |

**Notes on the board.** Moves and landings could play notes from one scale, so a game makes a tune: the pitch from the square's rank or file, or from the piece. Lichess already does this: its Pentatonic set plays one of 24 pitches from the destination square, and it is opt-in, not the default. Decide in the design pass whether it is pleasant over 80 moves or gets tiring; if we try it, make it a later toggle once the core set exists.

**Street soundtrack.** A quiet loop under the game: traffic, horns, sirens going past, a train on an elevated line or a subway platform, maybe a bus kneeling or a sanitation truck. It could swell with the game (more sirens when a king is in check, a train passing when a clock runs low) or stay a flat bed. No chess site we looked at has an ambient soundtrack, so there is no pattern to copy.

**Research (2026-10-07):** how Lichess, Chess.com, PyChess and others handle sound, with sources: [`2026-10-07-13-sound-research.md`](../specs/2026-10-07-13-sound-research.md).

**The demo (2026-10-08, branch `sound-demo`):** `web/src/lib/sound.ts` plays the clips through Web Audio after the first tap, with one speaker button on the game, practice and quick-match pages (`sound-off` in localStorage). Sounds follow `Animator.onreveal`, so only a turn that plays out sounds; a reload, a reconnect or a hidden tab plays nothing. Which moment plays which clip is `soundCues.ts`; each throw of the dice rattles, with a one-die clip for the pothole roll and a saving roll and a two-dice clip for the file and rank dice (both from Pixabay). A pothole opens with a bone crack or an ice shatter, picked at random (with the fall, when a piece falls in), and a hole closing on its own hisses (Pixabay steam), once however many close; one the cap pushes out closes quietly. A piece falling into a pothole plays SFX `Explosion` as it drops; the Mamdani gets only the crowd's gasp. A repair plays one of two clips at random (the Hearts of Iron IV construction, a drill) with its celebration (cone, sparks). A saved piece chimes (SFX `Confirmation`) and a re-roll buzzes (SFX `OutOfBound`). Players also hear SFX `LowTime` once as their clock drops under 10 s, `NewChallenge` when the opponent offers a rematch, and `GenericNotify` as a game starts (not on a reload). Tapping a piece that can't move (the other side's, one with no moves, or any while the opponent plays) plays SFX `Error` and the piece shakes its head (`Board`'s `onrefuse`); spectators' taps do nothing. Clips are mono 64 kbps MP3s with hashed names (about 303 KB in all, cached for a year); a page downloads only its own, after the first tap, and none with sound off. Credits: `web/src/lib/sounds/CREDITS.md`. The playtest starts its guests with sound off (`--sound` keeps it on).

**Recommended from the research (to confirm in the design pass):**
- **On or off.** Effects on after the first tap (browsers block audio until then); the street soundtrack off until the player turns it on. Lichess unlocks Web Audio on the first tap or keypress and checks the audio state before each sound, rebuilding it after an iOS interruption; do the same, without Howler.
- **Controls.** Two switches (effects, soundtrack) and a volume slider, kept in localStorage, reachable from the game page and the phone layout. Lichess keeps its volume (default 0.7) in localStorage too.
- **iOS silent switch.** Respect it: leave `navigator.audioSession` at its default (`ambient`), so the game goes quiet with the ringer off, which suits a game played in public. Audio also stops in a hidden tab.
- **Replays.** Sound only for turns that arrive live, never for a turn shown at once (a reload, a reconnect, the moves sheet). Lichess is silent on reload and reconnect. This is the same rule the dice re-throw needs (see "Known, left for later" in `CLAUDE.md`), so fix both together, first.
- **Spectators.** Moves, captures, check and the pothole sounds, but no win or loss sting and no low-clock alarm; Lichess does the same.
- **Event list.** Chess.com's file names suggest separate sounds for your move and your opponent's, plus check, castle, promote, illegal and a ten-second warning; consider the own/opponent split and an illegal-move sound alongside the table above.
- **Timing.** Dice and pothole sounds follow `web/src/lib/dice-timing.json`, so they stay in step with the board and the server's clock pause. Instant mode plays no sound.
- **Formats and size.** Small mono MP3s (Lichess's clips are about 2 to 8 KB each). Sources disagree on Opus in Safari, so test on a real iPhone before using it. Load the soundtrack only once it is turned on.
- **Rights (decided 2026-10-07).** The code is AGPL-3.0-or-later since then (`LICENSE`), so Lichess's AGPLv3+ sets by [Enigmahack](https://github.com/Enigmahack) are ours to use; the SFX set is the one kept. Credit Enigmahack and Lichess on the About page's Credits, with the licence. Lichess's default set is listed as non-free and lisp is non-commercial, so neither is used; Chess.com's are proprietary. Clips from myinstants.com state no licence, and several are sounds from commercial games (Metal Gear Solid, GTA V, Mortal Kombat X, Among Us), so each picked one needs a licensed source, our own recording or permission before it ships. CC0 clips are fine with a credit as a courtesy.
- **Still open.** Whether turning off motion also turns off sound.

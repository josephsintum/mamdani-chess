# Whole-codebase simplification (2026-10-19)

Seven reviewers read every file (rules, game, store/cmd/tools, server/contract, web TS modules, the game UI, the other routes; `match/` was read and is clean). This plan says what we change, in what order, and what we leave alone. Nothing in it changes behaviour: wire JSON, SSE framing, status codes and error strings, saved-game format and replay, migrations, counter meanings, dice faces, timings, and how every page looks stay as they are.

## Left alone (each changes behaviour; for the user to decide)

- The Header doesn't load `/api/me` on rules, about, how-to-play, practice and the error page, so the name die stays disabled there; on home a tab return fetches it twice.
- Possible bug: on `/play`, a quick-match retry still waiting on `me()` after the page has gone can call `goto()` and pull the player back.
- The phone breakpoint is 640px in Board and 639px elsewhere.
- DiceTray's straight apostrophe in `'s roll`.
- The moves sheet's end-of-game stats differ from the result card's `tallyOf`.
- `browsererror.go` cuts messages by bytes, which can split a UTF-8 character.
- `Connection: keep-alive` on SSE (revisit at the HTTP/2 check).
- A separate event kind for the cap's close (a wire change) would remove the before/after-roll guessing in the browser.

## Also left

- The catchphrase tests that re-type lines from `QUIPS`: they pin the copy on purpose.
- `tumbleFaces`' random generator stays apart from `feel.ts`'s `seeded` (merging them changes every face).
- The three stream-retry loops (game page, play, practice) and moving the game page's stream into `lib/stream.ts`: they differ in small ways, so unifying them risks behaviour for little gain.
- Pulling the celebration layer out of `Board.svelte`: too large for a no-change pass.
